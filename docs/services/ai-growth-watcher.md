# AI Growth Watcher

最終更新: 2026-07-31

## 目的

登録されたサイトを継続的に監視し、検索エンジンと AI に正しく理解され、問い合わせにつながるサイトへ育てる。

見た目の制作ではなく、内部構造、メタデータ、構造化データ、検索クエリ、問い合わせ導線を継続的に改善する運用型サービスとして設計する。

## 背景

今後の Web は、人間がブラウザで読むだけでなく、AI がサイトを読み、比較し、要約し、問い合わせ候補として提示する場所になる。

そのため、従来の SEO だけでなく、次の観点が重要になる。

- AI が誤解しない一次情報
- 明確なサービス構造
- FAQ
- 地域情報
- 構造化データ
- 画像 alt と文脈
- 更新履歴
- 問い合わせ導線
- Search Console / GA4 に基づく継続改善

## 対象

- 地域密着の小規模事業者
- 医療、福祉、整備、士業、工務店など、専門性がある業種
- Web の知識はないが、問い合わせを増やしたい事業者
- 既存サイトはあるが、内部設計が弱い事業者
- 生成 AI 時代の集客に不安がある事業者

## 最初の入口

最初から Search Console や GA4 の権限を求めない。

第 1 段階は URL だけで診断する。

- サイトが生きているか
- SSL 期限
- title / description
- canonical
- OGP
- robots.txt
- sitemap.xml
- JSON-LD の有無と構文
- 見出し構造
- 画像 alt
- 主要ページの内部リンク
- 問い合わせ導線
- フォーム到達性
- AI に読ませる一次情報の不足

診断結果を見せた後で、必要に応じて Search Console 連携を提案する。

## Search Console 連携で増える価値

- 実際に検索されている語句がわかる
- 表示回数はあるのにクリックされないページがわかる
- 伸びている悩み、地域、サービス名がわかる
- インデックス未登録やクロール問題がわかる
- FAQ 追加候補を根拠付きで出せる
- ページ追加やメタ改善の優先度を決められる

顧客には Google アカウントのパスワードを預からない。  
最初は閲覧権限の付与、または OAuth 連携を前提にする。

## 継続改善フロー

1. VPS から定期チェック
2. Search Console / GA4 / サイト構造を確認
3. 改善候補を作る
4. 優先度と期待効果を付ける
5. 顧客または西村州平に通知
6. 承認後に実装
7. 検証
8. 変更履歴と結果を残す

将来的には Butler 通知や GitHub Issue と連携する。  
ただし Butler が未完成の間は、メール、GitHub Issue、手動レポートで代替する。

## 改善候補の例

- FAQ 追加
- サービスページ追加
- 悩み別導線追加
- title / description 改善
- OGP 改善
- JSON-LD 追加
- 内部リンク追加
- 画像 alt 改善
- 問い合わせボタンの配置改善
- 低速ページの軽量化
- AI 向けサイト概要ファイルの整備

## 危険度分類

- 低: レポートのみ、承認不要
- 中: FAQ、メタ、内部リンクなど。承認後に実行
- 高: 医療表現、料金、対応範囲、会社情報。必ず人間確認
- 危険: 本番設定、DNS、認証、プラグイン更新。個別承認必須

## 収益化方針

最初はツール単体ではなく、運用込みで売る。

- URL 診断
- 月次チェック
- 改善提案
- 承認後の実装
- Search Console / GA4 レポート
- 構造化データ運用

小規模事業者に対しては、「AI 時代に見つけられるサイトへ育てる」という表現が伝わりやすい。

## 実証モデル

最初の実証モデルは恵義肢製作所。

同業他社が真似したくなるような、AI クロール、構造化データ、地域検索、問い合わせ導線に強いロールモデルサイトへ育てる。
